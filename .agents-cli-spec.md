# Agent Spec: Blackjack Strategy Tutor

## Overview
A text-based Blackjack gaming and tutoring agent built with the Google Agent Development Kit (ADK). The player plays Blackjack in a natural conversational loop. The Dealer Agent manages card dealing, game flow, bet resolution, and bankroll tracking. When a player attempts or proposes a mathematically suboptimal decision according to standard Blackjack basic strategy (e.g. hitting on hard 17+ or standing on hard 11), a Tutor Agent intercepts to analyze the move and explain the mathematically sound strategy.

## Architecture & Sub-Agents
- **Orchestration**: Multi-Agent Pattern.
  - **Dealer Agent (`dealer`)**: Fast model (`gemini-2.5-flash`), responsible for game flow, taking bets, dealing cards, tracking player/dealer hands, dealer drawing rules (dealer stands on 17+), and payout calculation.
  - **Tutor Agent (`tutor`)**: Analytical reasoning model (`gemini-2.5-pro`), responsible for evaluating the player's proposed action against dealer upcard and player hand total using basic strategy tables, explaining expected value and win/bust probabilities when intercepting suboptimal choices.
- **Interception Mechanism**: Dealer agent utilizes a strategy check tool/callback before finalizing a player's action. If suboptimal, the Tutor Agent is invoked to provide tactical feedback and advice.

## Example Use Cases
1. **Standard Play**:
   - Player starts with $1,000 bankroll.
   - Player bets $100.
   - Cards dealt: Player [10 of Spades, 8 of Hearts] (Total: 18). Dealer upcard: [6 of Diamonds].
   - Player actions: Stand. Dealer plays out, result resolved, bankroll updated.
2. **Strategy Tutor Interception**:
   - Player has [10 of Diamonds, 7 of Clubs] (Hard 17). Dealer upcard: 9.
   - Player inputs: "Hit".
   - Tutor intercepts: Explains that hitting on Hard 17 carries a ~69% bust probability and standing is the mathematically optimal choice under basic strategy. Player can reconsider or confirm.
3. **Guardrail / High-Risk Bet Confirmation (HITL)**:
   - Player bankroll is $1,000. Player attempts to bet $600 (>50% of bankroll).
   - ADK native `require_confirmation` gate halts execution: prompts player for explicit confirmation before placing the bet.

## Tools Required
All tools use strict Pydantic schemas, comprehensive docstrings, and type hints:
1. `deal_random_card()`: Deals a random standard card from a 52-card deck (Rank and Suit). Returns `Card` object.
2. `calculate_hand_total(cards: list[str])`: Computes optimal Blackjack hand total (accounting for soft Ace as 1 or 11). Returns total and `is_soft` flag.
3. `place_bet(amount: float)`: Validates and deducts bet from session bankroll. Uses `require_confirmation=True` when `amount > 0.5 * bankroll`.
4. `check_basic_strategy(player_cards: list[str], dealer_upcard: str, proposed_action: str)`: Validates the proposed action against standard basic strategy matrix. If suboptimal, returns `is_optimal=False` and strategy rationale to trigger Tutor intervention.
5. `resolve_hand(player_cards: list[str], dealer_cards: list[str], bet: float)`: Determines winner (Blackjack, Win, Loss, Push) and updates bankroll in session state.

## Context & Memory
- Session state (`tool_context.state` or `session.state`) persists across turns and hands:
  - `bankroll`: Virtual chip balance (initialized at $1,000).
  - `current_bet`: Active wager for the current hand.
  - `player_hand`: Cards held by player.
  - `dealer_hand`: Cards held by dealer.
  - `game_status`: State of the current hand (`betting`, `player_turn`, `dealer_turn`, `round_over`).

## Constraints & Safety Rules (Guardrails)
1. **HITL Bet Guardrail**: Hard stop triggered whenever a proposed bet exceeds 50% of the player's active bankroll (`bet > 0.5 * bankroll`). The bet tool requires explicit user confirmation via ADK confirmation handler.
2. **Dealer Drawing Rules**: Dealer must hit on 16 or lower, and stand on all 17s.
3. **No Fabricated Cards**: Cards must be dealt strictly through the deterministic dealing tool, not hallucinated by the LLM.

## Observability
- OpenTelemetry spans and structured JSON logging integrated with Cloud Trace.
- Logs structured events containing:
  - `intent`: User action intent (e.g., `{"event": "player_intent", "action": "hit", "player_total": 17, "dealer_upcard": "9"}`).
  - `outcome`: Result of action (e.g., `{"event": "action_outcome", "action": "hit", "card_drawn": "10 of Hearts", "new_total": 27, "status": "bust"}`).

## Success Criteria
1. **Functional Correctness**: 100% of dealt cards adhere to valid ranks/suits; Ace logic correctly adjusts between 1 and 11.
2. **Strategy Trigger Rate**: In eval test cases where the player makes a poor move (e.g., hit on hard 17+), the Tutor Agent intercepts 100% of the time.
3. **HITL Hard Stop**: Bets > 50% of bankroll trigger confirmation request in 100% of test scenarios.
4. **Structured JSON Logs**: Intent and Outcome are emitted as valid JSON records with all required fields in 100% of game turns.
5. **Session Persistence**: Bankroll correctly reflects wins, losses, and pushes across multiple hands.
